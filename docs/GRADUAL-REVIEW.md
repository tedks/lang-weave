## Approved policy continuation

The introduction allowance now counts a word only after the worker persists a visibility acknowledgement from a specific active document. A worker delivery reserves one of at most ten active slots for 30 seconds, so concurrent tabs cannot both claim the last slot. A reservation stores a word, opaque ticket and owner fingerprint, local day, expiry and revision; it stores no raw document/tab/frame identifier, page URL or text. At most twenty current and recently expired tickets persist for a renewal grace period of no more than one day. Only live tickets count against the allowance. The content script holds the English source in an owned span until acknowledgement succeeds, then reveals the target word. Unplaced batches release their reservations, hidden documents defer new reservations, and expired visible holds renew under the same lock without a model call. A failed acknowledgement retries with a bound, while a confirmed stale ticket leaves neighboring woven words intact. The card retains only a short-lived opaque replay receipt. The single acknowledgement can race with a document closing after it became visible; the visible placement path checks connectivity before sending. That narrow worker-save-to-render gap is an acknowledged limit of asynchronous browser messaging, and feature acceptance remains with the CTO.

Automatic inline recall requires the introduction gate day strictly earlier than today's browser-local calendar day; standalone review is available immediately. Manual introductions carry the same gate. Dates are compared as local calendar dates, so daylight saving changes and a time shortly before midnight do not impose a 24-hour delay. A saved budget day more than seven local calendar days ahead blocks introductions and displays a popup warning. Only an explicit popup recovery action for the same scope and saved day resets that budget; cancellation and write failure leave it intact. Cards, ratings, schedules, original introduction dates, current review and inline state are preserved. For a card introduced under the future clock, recovery separately records today's gate day, so due inline recall resumes no sooner than the next local day.
