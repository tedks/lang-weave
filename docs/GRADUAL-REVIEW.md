## Approved policy continuation

The introduction allowance now counts a word only after the worker persists a visibility acknowledgement from a specific active document. A worker delivery reserves one of at most ten slots for 30 seconds, so concurrent tabs cannot both claim the last slot. The reservation contains a word, opaque ticket, local day, expiry, revision and document identifiers; it stores no page URL or text. The content script holds the English source in an owned span until the acknowledgement succeeds, then reveals the target word. Unplaced batches release their reservations, hidden documents defer new reservations, and expired visible holds renew under the same lock without a model call. A failed acknowledgement retries with a bound, while a confirmed stale ticket leaves neighboring woven words intact. Expired and invalidated reservations are pruned by the next worker delivery. The card retains only a short-lived opaque replay receipt, not raw document identifiers. This favors a bounded temporary hold over silent overspending. The single acknowledgement can race with a document closing after it became visible; the visible placement path checks connectivity before sending. That narrow worker-save-to-render gap is an acknowledged limit of asynchronous browser messaging, and feature acceptance remains with the CTO.

Automatic inline recall requires `introducedDay` strictly earlier than today's browser-local calendar day; standalone review is available immediately. Dates are compared as local calendar dates, so daylight saving changes and a time shortly before midnight do not impose a 24-hour delay. A saved budget day more than seven local calendar days ahead blocks introductions and displays a popup warning. Only an explicit popup recovery action for the same scope and saved day resets that budget; cancellation and write failure leave it intact. Cards, ratings, schedules, current review and inline state are preserved.
